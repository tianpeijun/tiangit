# AWSomeShop 需求规划文档

## 项目概述
构建一个名为 AWSomeShop 的内部员工福利电商网站，通过 MVP 验证员工积分兑换系统的商业模式。

## 需求收集步骤

- [x] 1. 明确系统角色和权限
  - 确认系统中的用户角色（员工、管理员）
  - 确认每个角色的权限范围

- [x] 2. 员工功能需求澄清
  - [x] 2.1 产品浏览功能
    - [Question] 产品浏览需要支持哪些功能？（如：分类筛选、搜索、排序等）
    - [Answer] 需要支持浏览、搜索和分类筛选
    
    - [Question] 产品展示需要包含哪些信息？（如：图片、名称、所需积分、库存状态、描述等）
    - [Answer] 图片、名称、描述、价格、所需积分。
    
    - [Question] 是否需要产品详情页？如果需要，应该展示哪些详细信息？
    - [Answer] 需要产品详情页。需要展示产品图片、名称、描述、价格、是否存在库存、所需积分。
  
  - [x] 2.2 积分兑换功能
    - [Question] 兑换流程是怎样的？（如：选择产品 → 确认兑换 → 扣除积分 → 生成订单）
    - [Answer] 选择产品 → 确认积分→ 确认兑换 → 扣除积分 → 输入收货地址和电话→ 生成订单
    
    - [Question] 如果员工积分不足，系统应该如何处理？
    - [Answer] 直接弹窗提醒，结束兑换流程
    
    - [Question] 兑换是否需要确认步骤？是否可以取消已兑换的订单？
    - [Answer] 需要确认流程，不能够取消已兑换完成的订单
    
    - [Question] 产品是否有库存限制？如果库存不足应该如何处理？
    - [Answer] 不限库存
  
  - [x] 2.3 积分余额查看
    - [Question] 积分余额信息应该在哪里展示？（如：页面顶部、个人中心等）
    - [Answer] 在个人中心和登录后页面顶部都需要显示个人积分余额
    
    - [Question] 是否需要显示积分的获取来源和使用明细？
    - [Answer] 不需要显示积分获取的来源，但是需要展示积分使用明细
  
  - [x] 2.4 兑换历史查看
    - [Question] 兑换历史需要展示哪些信息？（如：兑换时间、产品名称、消耗积分、订单状态等）
    - [Answer] 兑换历史需要展示：兑换时间、产品名称、消耗积分、订单状态
    
    - [Question] 兑换历史是否需要支持筛选和搜索？
    - [Answer] 不需要
    
    - [Question] 兑换历史需要保留多长时间？
    - [Answer] 永久保存

- [x] 3. 管理员功能需求澄清
  - [x] 3.1 产品管理
    - [Question] 产品信息包含哪些字段？（如：产品名称、描述、图片、所需积分、库存数量、分类、状态等）
    - [Answer] 产品名称、描述、图片、所需积分、分类、状态
    
    - [Question] 管理员可以执行哪些产品操作？（如：添加、编辑、删除、上架/下架等）
    - [Answer] 添加、编辑、删除、上架/下架等
    
    - [Question] 产品图片如何上传和存储？是否有大小和格式限制？
    - [Answer] 图片上传元数据保存到数据库，图片文件本身直接存储到磁盘，大小限制为最大10MB，格式要求为png、jpg，一个产品限制为三个。图片直接在产品管理时候通过网页端上传
    
    - [Question] 是否需要产品分类管理功能？
    - [Answer] 需要产品分类管理功能
  
  - [x] 3.2 积分管理
    - [Question] 管理员如何给员工发放积分？（如：单个发放、批量发放、按规则自动发放等）
    - [Answer] 每个员工初始化1000积分，同时支持单个发放、批量发放。
    
    - [Question] 管理员如何扣除员工积分？是否需要填写原因？
    - [Answer] 不需要扣除员工积分
    
    - [Question] 积分操作是否需要审批流程？
    - [Answer] 不需要审批流程
    
    - [Question] 是否需要查看所有员工的积分情况？需要哪些统计信息？
    - [Answer] 不需要统计分析页面
    
    - [Question] 积分操作是否需要记录日志？日志需要包含哪些信息？
    - [Answer] 需要操作记录，需要对管理员操作记录进行记录

- [x] 4. 用户认证和授权
  - [Question] 员工如何登录系统？（如：公司邮箱、工号、SSO单点登录等）
  - [Answer] 不考虑司邮箱、工号、SSO单点登录，直接使用用户名和密码登录
  
  - [Question] 是否需要用户注册功能，还是由管理员统一创建账户？
  - [Answer] 不需要注册，直接管理员统一创建账户
  
  - [Question] 如何区分普通员工和管理员？是否需要角色管理功能？
  - [Answer] 只需要区分普通员工和管理员二种默认角色就行。不考虑角色管理功能

- [x] 5. 非功能性需求澄清
  - [x] 5.1 性能需求
    - [Question] 预计有多少员工使用该系统？
    - [Answer] 就内部100个员工使用该系统
    
    - [Question] 系统需要支持多少并发用户？
    - [Answer] 50个并发
    
    - [Question] 页面加载时间有什么要求？
    - [Answer] 3秒以内
  
  - [x] 5.2 安全需求
    - [Question] 是否需要 HTTPS 加密传输？
    - [Answer] 不需要
    
    - [Question] 密码策略有什么要求？（如：长度、复杂度、过期时间等）
    - [Answer] 长度6-8位，数字+字母就行
    
    - [Question] 是否需要防止恶意刷单或积分滥用的机制？
    - [Answer] 不需要
  
  - [x] 5.3 可用性需求
    - [Question] 系统的可用性目标是什么？（如：99.9% 可用性）
    - [Answer] 95%
    
    - [Question] 是否需要支持移动端访问？
    - [Answer] 不需要
    
    - [Question] 是否需要支持多语言？
    - [Answer] 不需要
  
  - [x] 5.4 数据需求
    - [Question] 数据需要备份吗？备份频率是多少？
    - [Answer] 不需要
    
    - [Question] 用户数据和交易数据需要保留多长时间？
    - [Answer] 用户和交易数据全部持久化到数据库，使用sqliter内存数据库就行
  
  - [x] 5.5 技术栈偏好
    - [Question] 是否有技术栈偏好？（如：前端框架、后端语言、数据库等）
    - [Answer] 前端使用Vue，后端使用python（fastAPI），数据库使用sqlite
    
    - [Question] 是否需要部署在特定的云平台？（如：AWS、Azure、阿里云等）
    - [Answer] AWS

- [x] 6. 业务规则澄清
  - [Question] 积分的有效期是多久？是否会过期？

  - [Question] 员工离职后，其积分和兑换记录如何处理？

  - [Question] 是否需要设置单次兑换的积分上限或产品数量限制？

  - [Question] 产品兑换后的配送流程是怎样的？系统是否需要跟踪配送状态？
  - [Answer] 不需要，只需要登记客户物流信息就可以
