# AWSomeShop 需求文档

## 简介

AWSomeShop 是一个内部员工福利电商网站，允许员工使用 AWSome 积分浏览和兑换预选产品。该系统旨在通过最小可行产品（MVP）验证员工积分兑换系统的商业模式。系统支持 100 名员工使用，最多 50 个并发用户，目标是在 2 天内完成开发。

## 术语表

- **系统**：AWSomeShop 员工福利电商网站
- **员工**：使用系统浏览和兑换产品的普通用户
- **管理员**：负责管理产品、分类、用户账户和积分的系统管理人员
- **AWSome积分**：员工用于兑换产品的虚拟货币单位
- **产品**：可供员工使用积分兑换的商品
- **产品分类**：用于组织产品的二级分类体系
- **订单**：员工完成产品兑换后生成的记录
- **积分明细**：记录员工积分变动的历史记录
- **操作日志**：记录管理员操作行为的日志记录
- **收货信息**：包含收货地址和联系电话的配送信息
- **账户状态**：用户账户的启用或禁用状态

## 需求

### 需求 1：用户认证

**用户故事**：作为员工或管理员，我想使用用户名和密码登录系统，以便访问相应权限的功能。

#### 验收标准

1. WHEN 用户输入有效的用户名和密码 THEN 系统应验证凭据并授予访问权限
2. WHEN 用户输入无效的用户名或密码 THEN 系统应拒绝访问并显示错误提示
3. WHEN 账户状态为禁用 THEN 系统应拒绝该账户的登录请求
4. WHEN 用户成功登录 THEN 系统应根据用户角色（员工或管理员）显示相应的功能界面

### 需求 2：员工产品浏览

**用户故事**：作为员工，我想浏览可兑换的产品列表，以便了解有哪些产品可以使用积分兑换。

#### 验收标准

1. WHEN 员工访问产品列表页面 THEN 系统应显示所有已上架产品的图片、名称、描述和所需积分
2. WHEN 员工在产品列表页面 THEN 系统应在页面顶部显示该员工的当前积分余额
3. WHEN 员工点击产品 THEN 系统应显示产品详情页，包含产品图片、名称、描述和所需积分
4. WHEN 产品列表包含多个产品 THEN 系统应支持按积分从低到高或按最新上架时间排序

### 需求 3：产品搜索和筛选

**用户故事**：作为员工，我想搜索和筛选产品，以便快速找到我感兴趣的产品。

#### 验收标准

1. WHEN 员工在搜索框输入关键词 THEN 系统应按产品名称进行模糊匹配并返回相关产品
2. WHEN 员工选择一个或多个产品分类 THEN 系统应显示属于所选分类的所有产品
3. WHEN 员工同时使用搜索和分类筛选 THEN 系统应返回同时满足两个条件的产品

### 需求 4：产品兑换

**用户故事**：作为员工，我想使用积分兑换产品，以便获得我需要的商品。

#### 验收标准

1. WHEN 员工在产品详情页点击兑换按钮 THEN 系统应显示确认对话框，展示所需积分和当前余额
2. WHEN 员工的积分余额小于产品所需积分 THEN 系统应显示积分不足提示并终止兑换流程
3. WHEN 员工确认兑换 THEN 系统应提示员工输入或确认收货地址和联系电话
4. WHEN 员工提交收货信息 THEN 系统应扣除相应积分、生成订单并将订单状态设置为已完成
5. WHEN 订单生成完成 THEN 系统应更新员工的积分余额并在积分明细中记录此次消费

### 需求 5：积分余额和明细查看

**用户故事**：作为员工，我想查看我的积分余额和使用明细，以便了解我的积分情况。

#### 验收标准

1. WHEN 员工登录系统 THEN 系统应在页面顶部显示该员工的当前积分余额
2. WHEN 员工访问个人中心 THEN 系统应显示该员工的当前积分余额
3. WHEN 员工查看积分明细 THEN 系统应显示每条记录的时间、消耗或获得的积分、相关产品（如适用）和操作后的剩余积分
4. WHEN 积分明细包含管理员发放的积分 THEN 系统应在明细中显示该发放记录

### 需求 6：兑换历史查看

**用户故事**：作为员工，我想查看我的兑换历史，以便了解我过去兑换了哪些产品。

#### 验收标准

1. WHEN 员工访问兑换历史页面 THEN 系统应显示该员工的所有历史订单
2. WHEN 系统显示兑换历史 THEN 每条记录应包含兑换时间、产品名称、消耗积分和订单状态
3. THE 系统应永久保存所有兑换历史记录

### 需求 7：收货信息管理

**用户故事**：作为员工，我想保存我的收货地址和电话，以便下次兑换时无需重复输入。

#### 验收标准

1. WHEN 员工首次兑换产品并输入收货信息 THEN 系统应将该信息保存到员工的个人资料中
2. WHEN 员工再次兑换产品 THEN 系统应自动填充已保存的收货地址和电话
3. WHEN 员工在个人中心 THEN 系统应允许员工查看和修改收货地址和电话
4. THE 系统应为每个员工仅保存一个收货地址和电话

### 需求 8：员工密码管理

**用户故事**：作为员工，我想修改我的登录密码，以便保护我的账户安全。

#### 验收标准

1. WHEN 员工在个人中心选择修改密码 THEN 系统应要求员工输入当前密码和新密码
2. WHEN 员工提交新密码 THEN 系统应验证新密码长度为 6 到 8 位且包含数字和字母
3. WHEN 新密码符合要求 THEN 系统应更新密码并提示修改成功
4. WHEN 新密码不符合要求 THEN 系统应显示错误提示并要求重新输入

### 需求 9：管理员用户管理

**用户故事**：作为管理员，我想管理员工账户，以便控制谁可以访问系统。

#### 验收标准

1. WHEN 管理员创建新员工账户 THEN 系统应要求输入用户名、密码、姓名、工号和部门
2. WHEN 管理员创建新员工账户 THEN 系统应为该员工初始化 1000 积分
3. WHEN 管理员创建账户时输入的密码 THEN 系统应验证密码长度为 6 到 8 位且包含数字和字母
4. WHEN 管理员编辑员工账户 THEN 系统应允许修改员工的姓名、工号、部门和账户状态
5. WHEN 管理员删除员工账户 THEN 系统应将该账户从系统中移除
6. WHEN 管理员禁用员工账户 THEN 系统应阻止该员工登录和兑换产品
7. WHEN 员工账户被禁用 THEN 系统应保留该员工的兑换历史记录供查询

### 需求 10：管理员密码重置

**用户故事**：作为管理员，我想重置员工的密码，以便帮助忘记密码的员工恢复访问。

#### 验收标准

1. WHEN 管理员选择重置某员工的密码 THEN 系统应允许管理员为该员工设置新密码
2. WHEN 管理员设置新密码 THEN 系统应验证新密码长度为 6 到 8 位且包含数字和字母
3. WHEN 新密码符合要求 THEN 系统应更新该员工的密码并提示操作成功

### 需求 11：管理员积分发放

**用户故事**：作为管理员，我想给员工发放积分，以便激励员工或补充积分余额。

#### 验收标准

1. WHEN 管理员选择单个员工发放积分 THEN 系统应允许管理员输入发放的积分数量
2. WHEN 管理员选择批量发放积分 THEN 系统应允许管理员输入积分数量并为所有员工发放相同数量的积分
3. WHEN 管理员确认发放积分 THEN 系统应增加相应员工的积分余额
4. WHEN 积分发放完成 THEN 系统应在员工的积分明细中记录此次发放

### 需求 12：管理员产品分类管理

**用户故事**：作为管理员，我想管理产品分类，以便组织和归类产品。

#### 验收标准

1. WHEN 管理员创建产品分类 THEN 系统应支持创建一级分类和二级分类
2. WHEN 管理员创建二级分类 THEN 系统应要求指定其所属的一级分类
3. WHEN 管理员编辑产品分类 THEN 系统应允许修改分类名称和层级关系
4. WHEN 管理员删除产品分类 THEN 系统应将该分类从系统中移除
5. WHEN 删除的分类下存在产品 THEN 系统应将这些产品的分类关联移除

### 需求 13：管理员产品管理

**用户故事**：作为管理员，我想管理产品信息，以便控制员工可以兑换的产品。

#### 验收标准

1. WHEN 管理员创建新产品 THEN 系统应要求输入产品名称、描述、所需积分、分类和状态
2. WHEN 管理员创建或编辑产品 THEN 系统应允许上传最多 3 张产品图片
3. WHEN 管理员上传产品图片 THEN 系统应验证图片格式为 PNG 或 JPG 且大小不超过 10MB
4. WHEN 管理员上传产品图片 THEN 系统应将图片文件保存到磁盘并将图片元数据保存到数据库
5. WHEN 管理员为产品指定分类 THEN 系统应允许产品属于多个分类
6. WHEN 管理员编辑产品 THEN 系统应允许修改产品的所有信息字段
7. WHEN 管理员删除产品 THEN 系统应将该产品从系统中移除
8. WHEN 管理员将产品状态设置为上架 THEN 系统应在员工的产品列表中显示该产品
9. WHEN 管理员将产品状态设置为下架 THEN 系统应在员工的产品列表中隐藏该产品

### 需求 14：管理员操作日志

**用户故事**：作为管理员，我想查看管理员的操作记录，以便审计系统操作和追踪变更。

#### 验收标准

1. WHEN 管理员执行产品管理操作 THEN 系统应记录操作时间、操作人、操作类型和操作内容
2. WHEN 管理员执行积分发放操作 THEN 系统应记录操作时间、操作人、操作类型和操作内容
3. WHEN 管理员执行用户管理操作 THEN 系统应记录操作时间、操作人、操作类型和操作内容
4. WHEN 管理员登录或登出系统 THEN 系统应记录操作时间、操作人和操作类型
5. WHEN 管理员访问操作日志页面 THEN 系统应显示所有操作记录

### 需求 15：系统性能

**用户故事**：作为系统用户，我希望系统响应迅速，以便高效完成操作。

#### 验收标准

1. WHEN 用户访问任何页面 THEN 系统应在 3 秒内完成页面加载
2. THE 系统应支持最多 50 个并发用户同时访问
3. THE 系统应支持最多 100 个员工账户

### 需求 16：数据持久化

**用户故事**：作为系统管理员，我希望所有数据被可靠保存，以便系统重启后数据不丢失。

#### 验收标准

1. THE 系统应使用 SQLite 文件数据库存储所有用户数据、产品数据、订单数据和操作日志
2. THE 系统应永久保存所有用户数据和交易数据
3. THE 系统应将产品图片文件保存到磁盘存储

### 需求 17：系统可用性

**用户故事**：作为业务负责人，我希望系统保持稳定运行，以便员工能够持续使用服务。

#### 验收标准

1. THE 系统应达到 95% 的可用性目标
